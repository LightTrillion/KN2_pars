# Доска объявлений об аренде жилья (Vue 3 + Vite)

Одностраничное приложение для просмотра объявлений об аренде жилья. Данные берутся
с сайта [kvartirant.ru](https://www.kvartirant.ru/) при помощи отдельного парсера
и сохраняются в `src/data/listings.json`. Все города собраны в один файл и
переключаются выпадающим списком в шапке приложения.

## Запуск

```bash
npm install          # установить зависимости
npm run parse        # (опционально) собрать свежие объявления по всем городам
npm run dev          # запустить приложение: http://localhost:5173
```

Продукционная сборка:

```bash
npm run build
npm run preview
```

Если парсер не запускать, приложение работает с уже сохранённым `listings.json`.
А если этот файл пуст, автоматически используются демо-данные из
`src/data/demoListings.js` (в том числе объявления с отсутствующими полями).

### Города

Все города парсятся в один `src/data/listings.json` и выбираются селектором
в шапке приложения — перезапускать парсер для переключения не нужно.

```bash
npm run parse                              # все города (по умолчанию)
npm run parse -- --pages=2 --details=16 --delay=200
npm run parse -- --city=spb                # обновить только Петербург
npm run parse -- --city=nsk --details=10   # обновить только Новосибирск
```

| `--city` | Город | Каталог |
| --- | --- | --- |
| `msk` | Москва | `www.kvartirant.ru/Moskva/sniat-kvartiru/` |
| `mo` | Московская область | `www.kvartirant.ru/Moskovskaya_obl/sniat-kvartiru/` |
| `spb` | Санкт-Петербург | `spb.kvartirant.ru/sniat-kvartiru/` |
| `lo` | Ленинградская область | `leningradskaya.kvartirant.ru/sniat-kvartiru/` |
| `nsk` | Новосибирск | `novosibirsk.kvartirant.ru/sniat-kvartiru/` |
| `all` | все перечисленные | — |

На момент проверки каталог Новосибирска отдал только 1 объявление — это
ограничение самого сайта, а не ошибка парсера.

При `--city=<ключ>` парсер загружает только этот город, но **не стирает** данные
остальных: в общем файле заменяется только соответствующая часть. Флаг
`--out=listings-test.json` позволяет записать результат в другой файл, не трогая
основной.

В JSON есть секция `cities` со списком городов, а у каждого объявления — поля
`cityKey` и `city`. В избранном id объявления составной (`cityKey:id`), поэтому
одинаковые номера в разных городах не конфликтуют. Старые записи в
`localStorage` автоматически относятся к городу по умолчанию (Москве).

## Что умеет приложение

- выбор города в шапке: Москва, Московская область, Санкт-Петербург,
  Ленинградская область, Новосибирск (данные всех городов загружены сразу);
- поиск по названию объявления (без учёта регистра);
- фильтры: цена «от/до», количество комнат (включая «4 и более»), район;
- отображение количества найденных объявлений («Найдено N из M»);
- добавление/удаление избранного, отдельный раздел «Избранное» (сохраняется в `localStorage`);
- подробная информация об объявлении в модальном окне: галерея фото, полное описание,
  характеристики, ссылка на оригинал;
- сортировка по цене и площади;
- понятное сообщение и кнопка сброса, если по условиям ничего не найдено.

Любое поле может отсутствовать: вместо него показывается «Цена не указана»,
«Площадь не указана», «Нет фотографий» и т.д. Приложение не падает.


## Как работает парсер

`npm run parse -- --city=all --pages=2 --details=16 --delay=200`

1. **Загрузка каталога.** Для каждого выбранного города (`--city=all` или один
   ключ) берётся свой домен и путь каталога (см. таблицу выше), затем axios
   запрашивает его страницы (`?page=N`).
2. **Разбор HTML.** `cheerio` строит DOM-дерево. В вёрстке несколько объявлений
   лежат внутри одного `.row`, поэтому их разбивают по блокам `.obj-data`
   («Добавлено: …»). Из каждого блока достаются:
   - `id` — из ссылки вида `/22998491/`;
   - заголовок и цена — из `<h3>` (цена отделяется регуляркой `за (\d+ …)`);
   - комнаты — из заголовка (`2-комнатную` → `2`);
   - площадь — из текста «Площадь: 40 м²»;
   - адрес — из строки «Адрес: …»;
   - метро — из ссылки с `metro-` в URL;
   - описание — из первого `<p>` (убираем ссылку «подробнее»);
   - фото — из `a.fancybox img` (заглушку `no_photo.png` отбрасываем).
3. **Детальные страницы.** Для первых `--details` объявлений загружается страница
   `/<id>/`. Там есть все фото (`.bxSlider`) и полный текст описания, а также
   уточнённая площадь. Новая информация заменяет базовую только если она непустая —
   это защищает от ситуации, когда на деталях что-то не нашлось.
4. **Район.** Прямого поля «район» сайт не даёт, поэтому `guessDistrict()`:
   ищет «р-н. Х» / «район Х», затем известные названия районов в адресе и описании,
   а если ничего не нашлось — подставляет метро (`м. Стрешнево`) или `null`.
5. **Устойчивость.** Каждое поле необязательно: `clean()`/`toNumber()` возвращают
   `null` вместо исключения, ошибки сети логируются и не прерывают весь процесс.
   Между запросами есть задержка (`--delay`), чтобы не нагружать сайт.
6. **Результат.** В `src/data/listings.json` пишется объект
   `{ meta, cities: [{ key, label, count, parsedAt }], listings: [...] }`.
   У каждого объявления есть `cityKey`/`city` и составной id для избранного.

Почему парсер — отдельный Node-скрипт, а не запрос из браузера: сайт не отдаёт
CORS-заголовки, поэтому напрямую из Vue страницу не загрузить. Кроме того, так
парсер можно перезапускать вручную и проверять его вывод.

## Как работает приложение

- `useListings()` импортирует JSON, нормализует каждое объявление (`normalize`)
  и хранит список в `shallowRef`. Селектор в шапке меняет `cityKey`; `computed`
  `cityListings` оставляет объявления только выбранного города, а фильтры и
  словарь районов пересчитываются под него.
- Фильтры лежат в `reactive`-объекте; `computed` `matchedListings` применят их
  последовательно, а `visibleListings` ещё и сортирует результат.
- Избранное — `ref` с массивом id; `watch` сохраняет его в `localStorage`.
- Клик по карточке открывает `ListingModal` через `Teleport` в `body`; закрытие —
  по крестику, клику по фону или клавише Esc, фото листаются стрелками.
- `defineModel()` в `FilterPanel` позволяет делать `v-model:search`,
  `v-model:price-min` и т.д. без ручного проброса событий.
